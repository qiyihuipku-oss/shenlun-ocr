# 系统地图

```text
手机/电脑浏览器
  ├─ 选择题目
  ├─ 压缩、旋转、排序答卷
  └─ 校对并确认电子稿
          │
          ▼
Next.js Web/API
  ├─ 文件类型、大小、所有权检查
  ├─ Submission 状态机
  ├─ 文本版本锁定
  └─ 结构化报告校验
      │         │          │
      ▼         ▼          ▼
Storage      OCRProvider  GradingProvider
R2/COS       百度作文OCR   千帆 JSON Schema
      │         │          │
      └─────────┴──────────┘
                │
                ▼
         D1 / PostgreSQL
```

## 状态机

`uploaded → quality_check → ocr_pending → ocr_processing → needs_review → confirmed → grading → completed`

## OCR 质量闭环

1. 浏览器检查分辨率、模糊和曝光，并生成去除 EXIF 的规范化副本。
2. 百度手写作文 OCR 按页创建持久化任务，返回真实坐标和置信度。
3. 低置信度页面按 `OCR_SECONDARY_MODE` 送往 PaddleOCR；`shadow` 模式不改变用户结果。
4. 引擎分歧和低置信度行生成 `OcrDecision`，必须由用户确认。
5. 用户修改生成 `CorrectionEvent`；只有明确授权为 `improvement` 才进入后续改进清单。

核心表：`ocr_runs`、`ocr_candidates`、`correction_events`、`data_consents`、`quality_checks`。

任何异步阶段都可以进入 `failed`。重试必须复用原任务的幂等键，不能重复扣费或生成两份报告。

## 关键边界

- OCR 只还原考生写了什么，不负责优化表达。
- 语境校正只能提出候选，不能静默替换。
- 批改只读取当前题目版本和确认稿。
- 每个采分点命中必须有原文证据。
- 图片默认 30 天清理，文本与报告由用户主动删除。
- 姓名、学号、班级不进入分析字段。

## 可替换接口

- `StorageProvider`：Sites R2、腾讯 COS 或其他 S3 兼容存储。
- `OcrProvider`：百度作文 OCR、腾讯 OCR、PaddleOCR。
- `GradingProvider`：任何支持 JSON Schema 的国内模型。

替换供应商时不得改动前端报告契约；先运行黄金集回归，再切换生产环境。
